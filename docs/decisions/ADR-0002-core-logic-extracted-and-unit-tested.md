# ADR-0002：判据抽到 `core/` 并单测

- 状态：已采纳
- 日期：2026-10-15

## 背景

源工程用 Kotlin 单元测试（`src/test/` 25 个类 / 273 用例）锁住判据。移植到 ArkTS 后，
可以用 `hypium`（框架自带，需真机或模拟器）或自建 npm 测试。

## 决策

**把"判据"抽成 `core/` 下的纯函数/纯类，用独立 npm 测试工程（`test/`）覆盖；框架测试不跑。**

判据包括：URL 拼装、选路排序、配置导入解析、Markdown 块级切分、会话呈现、
错误码归类、列表序号等——共同点是**纯输入输出，不碰系统 API**。

## 理由

1. **速度**：`cd test && npm test` 在电脑上秒级出结果，531 用例全跑一遍的成本极低；
   框架测试要起设备。
2. **可移植性**：`core/` 不 import `@ohos.*`，因此可在 Node 下直接执行——
   `platform/Platform.ets` 被刻意排除在外，它是**唯一无法离线单测的一层**。
3. **判据可复用**：单测本身就是给后来者的规格说明。

## 后果

- **代价**：`core/` 必须维持"不碰系统 API"的纪律，否则测试立刻跑不起来；
  需要平台能力的逻辑只能放 `ui/` 或 `platform/`，那些地方天然缺单测。
- **代价**：需要人工保持"源码树"与"测试工程"两份 tsconfig 一致。
- **收益**：跨模块 `instanceof` 失效这类**测试基建缺陷**暴露得早
  （曾伪装成业务 bug，六个用例全挂，见 `PORT-MAP.md` §1b）。
- **收益**：表格列宽、行内标记这一类"屏幕上说不清"的问题，有了可断言的判据。
