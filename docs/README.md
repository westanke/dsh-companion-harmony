# 文档索引

每轮开工先读 `STATUS.md`；改代码前读 `PORT-MAP.md` §6 对应坑位。

| 文件 | 什么时候读 |
|---|---|
| `STATUS.md` | **每轮开工先读**：现在到哪了、版本、最近验证数据 |
| `PORT-MAP.md` | Android → HarmonyOS 移植对照（§4）、坑位（§6，名字 = 锚点）、收尾记录（§7） |
| `ARCHITECTURE.md` | 为什么这么设计（分层、数据流、契约） |
| `CHANGELOG.md` | 这次改了什么（Keep a Changelog 1.1.0；改动先追加 `[未发布]` 段） |
| `RELEASE.md` | 发版顺序与签名（`.hap` / `.app` 里外双签） |
| `TESTING.md` | 测试口径与用例数演进 |
| `SECURITY.md` | 签名、令牌、备份边界 |
| `store-listing.md` | 中英文上架文案 |
| `screenshots/` | 上架截图（1080×1920，严格 9:16） |

## 工程宪法

`AGENTS.md`（仓库根）是每次会话必然读到的那份约定：命令口径、版本与文档同步铁律、
架构纪律、测试纪律、对外表述纪律、坑位索引。**规矩写在那里，不靠记忆、不靠口头。**

## 新增文档的规矩

- 长效文档必须在上表挂一行，**目标没了删行防死链**。
- 「说不清、要摆证据」的内容进 `docs/`；`AGENTS.md` 只留指针。
- 新坑位 = 名字加进 `AGENTS.md` §7 清单 + 原文写进 `PORT-MAP.md` §6 并补 `### 同名` 锚点。
