### 设备侧验证（本轮新增两项，2026-10-20 **已做，逐条见标注**）

这两项**离线单测都只能钉住前半段**（切分对不对、降级链对不对），钉不住「点上去真的开了」，
故在装带本轮改动的包（`13dbdea` 调试签名）上过了一遍。**已实测，逐条标注**：

**A. 正文文件链接化（源 `a344e3f` 那条真机反馈的复现路径）**

1. 找一个助手正文里**以纯文本写过已知文件名**的会话（例如「已落盘：xxx.md」）；
   该文件名必须**在本会话文件清单里是唯一的**（同名多目录的**刻意不替换**，见 `PathLinks` 判据）。
   ✅ 现场：`dsh-public-deployments-项目适配评估-2026-10-19.md`。
2. 该文件名应显示为**链接色 + 下划线**；点它 → 打开「本会话的文件」面板并定位到该文件。
   ✅ **已验**：呈蓝色带下划线链接态；按坐标（`600,1660`）点击后打开「文件详情」、路径解析正确。
3. 交叉验：正文里**本来就是 Markdown 链接**的 `[文字](/abs/path)` 与 `<https://…>`：
   前者应能被点开（服务端路径 → 文件面板；`http(s)` → 外部浏览器），不得出现 `[[t](p)](p)` 这类套娃。
   ⚠️ **未单独触发**：本轮现场会话里没有这类形态可点。
4. **相对路径**那一支：点一个形如 `docs/x.md` 的已知文件，应有提示而不是静默无反应。
   ⚠️ **未单独触发**：同上，本轮未造该现场。

**B. 顶栏权限档位胶囊（`PermissionCatalog` + `permissionPresets()`）**

1. 进会话页：顶栏「已连接」后应出现**小胶囊**，宽度**贴着文字**（**不得独占整行** —— 这是
   用户 2026-10-19 反馈「影响页面可视区域」的直接判据）。
   ✅ **已验**：内层文本 bounds `[359,382][497,422]`，宽约 138/1080。
2. 点胶囊 → 应列出候选档位；选一个 → 顶栏标签与会话的当前档位**同步变化**
   （建议对着 ⋯ 菜单里那一段交叉看，两处必须同源同值）。
   ✅ **候选已验**（3 项：只读 / 工作区写入 / ✓ 完整访问）；
   ✅ **切换链路已验**（服务端双取证：审计库 `chat.command.execute` × 2 + 会话事件流
   `command/run` → `permission/preset` → `sandbox/mode` → `approval/policy` → `command/done(success)` 闭合）；
   ⚠️ **胶囊弹窗里「点某一行」这一步未单独触发** —— `uitest uiInput click` 与 `uinput -T -c`
   **都无法驱动 ArkUI `bindMenu` 弹出的 `Option` 项**（注入点击被弹窗当作 dismiss 吞掉），
   属**工具局限、非代码缺陷**（同一动作的 ⋯ 菜单路径已验通，胶囊与菜单同源同值）。
3. `danger-full-access` 必须**弹二次确认**才生效。
   ⚠️ **未单独触发**：注入点击驱动不了弹窗项，故这条二次确认框本轮未走到（代码路径与 ⋯ 菜单一致）。
4. **老 bridge 分支**：若服务端 bridge < 2.4.2（`GET /chat/permission-presets` 返 404），
   胶囊应**仍显示当前档位但点不开**，且**连接本身不能失败** —— 这是本轮坑 47 的现场判据。
   ⚠️ **未验**：本机服务端 bridge ≥ 2.4.2，无老 bridge 环境可造。
